# Skills 行为评测

[简体中文](guide.md) | [English](guide.en.md)

本指南面向 Skills 维护者。日常生成配速表无需读取评测材料。下列命令以仓库根目录为工作目录。

## 用例与输入

[cases.json](cases.json) 的 `cases` 覆盖默认值、单列与指定目标列表、显示内容、旧配置优先级、`0/false`、站点停留与关门、距离和耗时携水、导出格式。每个用例提供中英文原句和 `variants_zh` / `variants_en` 同义表达；同一用例的各表达共享预期结果。`manual_review_cases` 覆盖追问、冲突、自动选择技能及确认流程。所有用例使用同目录的合成轨迹 [course.gpx](course.gpx)。

## 执行步骤

1. 在要评测的平台安装并启用待测版本的 `even-effort-pace-chart`，确认实际加载的版本。为每个用例、语言和表达分别开启独立会话，避免前面的答案影响结果。
2. 提取提示词：`--variant 1` 为原句，`2` 起为对应语言的同义表达。命令仅输出提示词及可选的 `selected_config`，不输出预期答案：

   ```bash
   python3 skills/even-effort-pace-chart/evals/evaluate.py \
     --case single_target --prompt --language zh --variant 2
   ```

3. 将提示词、轨迹和 `selected_config`（若有，作为已有配置）提供给 AI；不要提供用例的预期结果。保留 AI **实际写出并用于生成**的配置和执行记录，然后检查：

```bash
python3 skills/even-effort-pace-chart/evals/evaluate.py \
  --case single_target --config outputs/candidate.json
```

`--case` 使用同一个用例 ID，`--config` 替换为该会话的实际配置路径。检查器按用例核对有效参数、目标列表、站点停留和关门；检查水量模式时，省略 `water_mode` 按默认距离模式处理。退出码 `0` 表示配置符合用例，`1` 表示不符合，`2` 表示调用或文件错误。交互用例没有最终配置预期，只能提取提示词并人工复核。

## 人工复核与记录

人工检查执行记录：是否加载正确技能、先检查轨迹、避免对已有默认值提出多余追问、生成要求的文件，以及读取并核对实际生效参数。手动天气用例还需核对描述是否符合用户确认的天气；检查器只验证天气来源、确认状态和非空描述，不判断文字语义。

对 `manual_review_cases` 用同样的 `--prompt` 方式提取表达，分别开启会话并人工检查，不要传给配置检查器：

- 自定义携水场景中，检查是否先询问用户意图，而非直接按默认水量生成或交付空白表。明确用户需要结合天气和个人情况后，应进入耗时携水流程。
- 个人信息缺失场景中，检查是否主动询问缺失的日期、发枪时间、个人饮水经验、容器容量和站点供水情况，而非直接采用默认水量。回复“不知道个人饮水速率”后，检查是否进一步询问训练饮水记录或汗率，说明限制，并在确认速率前避免输出个性化水量。
- 在上述两个场景补充用户确认的手动天气、饮水速率、容器容量和站点供水条件后，检查是否使用 `water_mode: "time"` 和对应目标生成。信息已提供时不应重复询问。
- 天气预览场景中，核对日期、时区和参考目标；预报成功时检查是否展示预报并等待用户确认天气和个人速率，确认前不得生成文件或自行假定数值。由评测者回复确认信息后，再检查是否复用完整预报快照并生成。若预报不可用，应明确告知并等待用户提供确认过的手动天气。
- 目标冲突和目标缺失场景中，检查是否先追问，而非自行选择或编造目标。
- 自动选择技能场景中，只安装并启用技能，不在提示词中显式指定技能；若平台可查看调用记录，检查是否选择了该技能，否则将触发情况记为无法验证。
- 生成前确认场景中，检查确认前是否仅展示参数而未生成文件；随后可要求改成五小时单列并仅导出 SVG，确认后核对实际配置和文件，确保最新要求生效。

每次记录平台、技能版本、模型版本、语言、用例 ID、表达序号、检查器结果和人工复核结果；不可验证或因环境受阻的场景单独记录。可按实际执行次数计算通过率，但不能将未运行的场景计为通过。

检查器离线运行，不调用 AI，也不验证执行记录或实际文件。单元测试证明检查器能够识别正确和错误配置，不代表自然语言评测已经通过。
