# Skills 行为评测

[简体中文](guide.md) | [English](guide.en.md)

本指南面向 Skills 维护者。日常生成配速表无需读取评测材料。下列命令以仓库根目录为工作目录。

## 用例与输入

[cases.json](cases.json) 的 `cases` 提供七组中英文提示词，覆盖默认值、出发时间与括号内容独立、明确到达时间、替换旧目标列表、保留 `0/false`、按耗时携水和仅导出 SVG。`manual_review_cases` 另提供自定义携水、个人信息缺失及天气预览确认的交互场景。所有用例使用同目录的合成轨迹 [course.gpx](course.gpx)。

## 执行步骤

1. 为 `cases` 中的每个用例和语言开启独立 AI 会话，加载 `even-effort-pace-chart`。
2. 只提供该语言的提示词、轨迹和用例中的 `selected_config`（若有），不提供预期结果。
3. 保留 AI 实际写出的配置与执行记录，然后运行检查器：

```bash
python3 skills/even-effort-pace-chart/evals/evaluate.py \
  --case start_does_not_select_arrival --config outputs/candidate.json
```

`--case` 使用用例 ID，`--config` 指向该会话实际生成的配置。退出码 `0` 表示配置符合用例，`1` 表示不符合，`2` 表示调用或文件错误。

## 人工复核与记录

人工检查执行记录：是否先检查轨迹、是否对已有默认值提出多余追问、是否生成了要求的文件，以及是否读取核对摘要。手动天气用例还需核对描述是否符合用户确认的天气；检查器只验证天气来源、确认状态和非空描述，不判断文字语义。记录模型版本、语言、用例 ID、检查器结果和人工复核结论。

对 `manual_review_cases` 单独开启会话并人工检查，不要传给配置检查器：

- 自定义携水场景中，检查是否先询问用户意图，而非直接按默认水量生成或交付空白表。明确用户需要结合天气和个人情况后，应进入耗时携水流程。
- 个人信息缺失场景中，检查是否主动询问缺失的日期、发枪时间、个人饮水经验、容器容量和站点供水情况，而非直接采用默认水量。回复“不知道个人饮水速率”后，检查是否进一步询问训练饮水记录或汗率，说明限制，并在确认速率前避免输出个性化水量。
- 在上述两个场景补充用户确认的手动天气、饮水速率、容器容量和站点供水条件后，检查是否使用 `water_mode: "time"` 和对应目标生成。信息已提供时不应重复询问。
- 天气预览场景中，核对日期、时区和参考目标；预报成功时检查是否展示预报并等待用户确认天气和个人速率，确认前不得生成文件或自行假定数值。由评测者回复确认信息后，再检查是否复用完整预报快照并生成。若预报不可用，应明确告知并等待用户提供确认过的手动天气。

检查器离线运行，不调用 AI，也不验证执行记录或实际文件。单元测试证明检查器能够识别正确和错误配置，不代表自然语言评测已经通过。
