# 爬升算法方案与选择依据

[简体中文](ascent-options.md) | [English](ascent-options.en.md)

**默认采用不平滑＋10 米峰谷反转阈值。** 在所测的二十次越野跑活动中，该方案整体最接近佳明显示值，同时避免窗口平均进一步削弱短坡。其他平滑窗口保留为显式选项。

## 历史方案对比

同一批二十次活动使用相同的原始 FIT 坐标与海拔输入，与佳明活动显示的累计爬升、下降比较。平均绝对差异为逐次差值取绝对值后求平均；平台显示值不等于地形真值。

| 方案 | 爬升平均绝对差异（米） | 下降平均绝对差异（米） |
| --- | ---: | ---: |
| 旧版100米窗口 | 110.5 | 111.3 |
| **不平滑＋10米阈值（默认）** | **71.4** | **71.9** |
| 40米平滑＋10米阈值 | 105.9 | 107.0 |
| 20米平滑＋10米阈值 | 88.6 | 89.7 |
| 10米平滑＋10米阈值 | 79.1 | 79.9 |

## 徽州古城的赛前检查与赛后对照

### 赛前 GPX 检查

在同一份赛前 GPX 上，不平滑与旧版相差约634米，其中 **77.9%集中在CP3→CP6**。当时未发现可确认删除的孤立大尖峰或CP边界海拔突跳，独立转折点累计也得到5965.47米。这只排除了已检查的异常形式，不证明连续起伏都是真实地形。

差异主要来自连续起伏跨越10米阈值：例如一段原始下降12.81米，40米平滑后局部幅度约7.73米，便可能不再确认一次下坡转折。这些起伏是否真实，仍需独立高程数据验证。

补充实验中，60米平滑＋10米阈值得到5290.0米，100米平滑＋10米阈值得到4895.4米；仅每5米重新取点、不做平均平滑，得到5935.7米。接近高驰约5300米不能单独证明方案更准确，也不据此删点或调参。

### 赛后 FIT 对照

2026-10-31 完赛后，以实际 FIT 的设备距离与逐点海拔重算路线，得到约4783米爬升；佳明平台显示5019米，赛前 GPX 则约5965米。三者输入或统计口径不同，未按比例对齐。

同一套不平滑＋10米算法下，CP3→CP4 的爬升从 GPX 的844.8米变为 FIT 的635.2米，CP5→CP6 从722.6米变为273.0米。对照位置可见原 GPX 有多点连续起伏，FIT 对应位置波动较小。连续起伏超过阈值仍会被计入，不能用“没有孤立尖峰”推导出输入无误。

这些结果是新的对照证据，不是实测高程验证，也不据此自动改变默认参数。完整区间爬升、下降和配速影响见[徽州古城示例](https://github.com/yihouzenmeban/trail-running-pace/blob/main/examples/huizhou-gucheng-100k/README.md#赛后活动对比)；个人 FIT 未公开，该部分仅供查看和理解口径。

## 如何选择

默认无需额外配置，等价于：

```json
{
  "ascent_method": "hysteresis",
  "ascent_smoothing_m": 0,
  "ascent_threshold_m": 10
}
```

- **不平滑＋10米阈值**：保留清理后原始海拔的峰谷；超过阈值的噪声仍可能计入爬升。
- **显式平滑**：将 `ascent_smoothing_m` 设为10、20、40等正数；窗口平均可能削弱真实短坡。窗口为完整宽度，如40米表示前后各20米。
- **窗口法**：不使用反转阈值；设置和旧版兼容说明见[配置文档](configuration.md#旧窗口口径与显式过滤)。

10米阈值针对累计反向变化，不是相邻点高差。显示曲线独立使用5米采样、20米平滑；默认保留重复点处理和孤立尖峰修正。详细规则见[模型](model.md#累计爬升与下降)，参数见[配置](configuration.md#参数)。
